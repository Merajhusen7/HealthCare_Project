# Healthcare Database

## What is running

This project uses a PostgreSQL Docker database as a local, self-hosted implementation of the ER design. It also includes pgAdmin for browsing tables and running queries.

Snowflake does not provide an official local database Docker image. Snowflake is a managed cloud database. The SQL is written as portable SQL and can be adapted to Snowflake by replacing PostgreSQL-specific defaults and types.

## Start

On Windows PowerShell:

```powershell
cd C:\Users\meraj\OneDrive\Desktop\Class_Project\Healthcare_Project
Copy-Item .env.example .env
docker compose up -d
```

Open pgAdmin:

- <http://localhost:5050>
- Email: `admin@example.com`
- Password from `PGADMIN_PASSWORD` in `.env`

Add the PostgreSQL server in pgAdmin:

1. Host: `postgres`
2. Port: `5432`
3. Maintenance database: `healthcare`
4. Username: `healthcare_admin`
5. Password from `POSTGRES_PASSWORD` in `.env`

## Useful commands

```powershell
docker compose ps
docker compose logs postgres
docker compose exec postgres psql -U healthcare_admin -d healthcare
docker compose down
```

To remove database data and recreate it:

```powershell
docker compose down -v
docker compose up -d
```

## Tables

The schema implements every entity in `ER_DIAGRAM.mmd`:

- Patient and authentication: `patient`, `patient_account`, `account_session`
- Address and consent: `patient_address`, `consent`
- Doctors: `doctor`, `specialty`, `doctor_specialty`
- Facilities and scheduling: `facility`, `doctor_availability`
- Services: `service_category`, `health_service`, `doctor_service`
- Appointments: `appointment`, `appointment_service`, `appointment_status_history`, `appointment_action`
- Requests and results: `service_request`, `service_request_status_history`, `request_result`, `result_document`

## Snowflake deployment mapping

For a real Snowflake account, deploy the same logical tables to a Snowflake database/schema and map types:

| PostgreSQL | Snowflake |
|---|---|
| `UUID` | `VARCHAR(36)` or Snowflake `UUID` string convention |
| `TIMESTAMPTZ` | `TIMESTAMP_TZ` |
| `TIMESTAMP` | `TIMESTAMP_NTZ` |
| `JSONB` | `VARIANT` |
| `NUMERIC(p,s)` | `NUMBER(p,s)` |
| `VARCHAR(n)` | `VARCHAR(n)` |
| `BOOLEAN` | `BOOLEAN` |
| `CHECK` constraints | Snowflake enforces only some constraint types; validate statuses in application or procedures |

Recommended Snowflake objects:

- Database: `HEALTHCARE`
- Schema: `PATIENT_APP`
- Warehouse: `HEALTHCARE_WH`
- Role: `HEALTHCARE_APP_ROLE`
- Stages: for document metadata import/export only; keep actual documents in encrypted object storage

The complete Snowflake DDL is available in [sql/00_snowflake_schema.sql](./sql/00_snowflake_schema.sql). Replace `VARCHAR(36)` identifiers with UUID strings generated by `UUID_STRING()` if Snowflake application procedures create the records.
